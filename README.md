# Pemos Portfolio

A high-performance, security-focused static multi-page web application built for cybersecurity researchers and vulnerability engine developers. The project serves as an interactive portfolio for showcasing tools, research projects, CTF write-ups, and security disclosures.

## 🌟 Key Features

* **Nord Dark Theme Architecture:** Modern, clean, and responsive user interface tailored for technical documentation and code display.

* **Client-Side Markdown Rendering:** Dynamic parsing of Markdown content using **Marked.js** and syntax highlighting via **Highlight.js**.

* **XSS Protection:** Strict HTML sanitization using **DOMPurify** before DOM insertion to prevent cross-site scripting vulnerabilities.

* **Serverless Backend:** Powered by **Supabase** for dynamic database queries and authentication.

* **Row Level Security (RLS):** Granular access controls ensuring public read access while restricting write/publish capabilities strictly to the verified project owner.

* **Hidden Owner Portal:** Lightweight publishing interface accessible via hotkey (`Ctrl + Shift + A`) or URL fragment (`#pemos_admin`).

## 🏗️ Architecture & Project Structure

The project is structured as a zero-build static site requiring no complex bundling pipelines.

## 🔒 Database & Supabase Configuration

The frontend interacts with Supabase using standard public client libraries. Database security is strictly enforced via **Row Level Security (RLS)** policies.

### SQL Schema Setup

Execute the following SQL commands inside the Supabase **SQL Editor** to set up the database tables and safety policies:

```
-- 1. Create Projects Table
create table if not exists public.projects (
  id bigint generated by default as identity primary key,
  title text not null check (char_length(title) between 1 and 160),
  description text not null check (char_length(description) <= 2000),
  repo_url text not null check (repo_url ~ '^https?://(www[.])?github[.]com/'),
  technologies text[] not null default '{}',
  created_at timestamptz not null default now()
);

-- 2. Create Writeups Table
create table if not exists public.writeups (
  id bigint generated by default as identity primary key,
  title text not null check (char_length(title) between 1 and 200),
  tags text[] not null default '{}',
  summary text not null check (char_length(summary) <= 1000),
  content text not null check (char_length(content) <= 1000000),
  created_at timestamptz not null default now()
);

-- Ensure tags column exists for legacy installations
alter table public.writeups add column if not exists tags text[] not null default '{}';
alter table public.writeups add column if not exists summary text not null default '';

-- 3. Enable Row Level Security (RLS)
alter table public.projects enable row level security;
alter table public.writeups enable row level security;

-- 4. Define Security Policies (Replace Owner UUID with your Authentication User UUID)
create policy "Anyone can read projects" on public.projects
  for select to anon, authenticated using (true);

create policy "Owner can add projects" on public.projects
  for insert to authenticated
  with check ((select auth.uid()) = 'fdbff77c-0935-4902-b22a-4c9b7fd2ed4e'::uuid);

create policy "Anyone can read writeups" on public.writeups
  for select to anon, authenticated using (true);

create policy "Owner can publish writeups" on public.writeups
  for insert to authenticated
  with check ((select auth.uid()) = 'fdbff77c-0935-4902-b22a-4c9b7fd2ed4e'::uuid);

-- 5. Grant Permissions
grant select on public.projects, public.writeups to anon, authenticated;
grant insert on public.projects, public.writeups to authenticated;
grant usage, select on all sequences in schema public to authenticated;

```

## 🚀 Deployment & Local Setup

Because the site relies on browser modules and CORS policies, serve the project using a local or remote web server over HTTPS. **Opening files directly via `file://` will break browser module resolution and Supabase queries.**

### Local Development

You can run a local HTTP server using Python or Node.js:

```
# Using Python 3
python3 -m http.server 8000

# Using Node.js (serve)
npx serve .

```

Access the application at `http://localhost:8000`.
