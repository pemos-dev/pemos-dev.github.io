# Pemos portfolio

A static, multi-page cybersecurity researcher portfolio. Serve this directory over HTTPS (or use a local static server); opening pages directly with `file://` can prevent browser modules and database requests from working.

## Supabase setup

The browser uses the supplied Supabase URL and publishable key in `js/supabase.js`. A publishable key is visible to every visitor by design. It is safe only when database permissions are enforced with Row Level Security (RLS). Do not put a `service_role` or secret key in this site.

Run this SQL in the Supabase SQL editor. Replace `OWNER_AUTH_USER_UUID` with the UUID of the owner account from **Authentication → Users**. Create the owner account yourself and disable public sign-ups in Supabase Auth settings.

```sql
create table if not exists public.projects (
  id bigint generated by default as identity primary key,
  title text not null check (char_length(title) between 1 and 160),
  description text not null check (char_length(description) <= 2000),
  repo_url text not null check (repo_url ~ '^https?://(www[.])?github[.]com/'),
  technologies text[] not null default '{}',
  created_at timestamptz not null default now()
);

create table if not exists public.writeups (
  id bigint generated by default as identity primary key,
  title text not null check (char_length(title) between 1 and 200),
  summary text not null default '' check (char_length(summary) <= 1000),
  content text not null check (char_length(content) <= 1000000),
  created_at timestamptz not null default now()
);

alter table public.projects enable row level security;
alter table public.writeups enable row level security;

create policy "Anyone can read projects" on public.projects
  for select to anon, authenticated using (true);
create policy "Owner can add projects" on public.projects
  for insert to authenticated
  with check ((select auth.uid()) = 'OWNER_AUTH_USER_UUID'::uuid);
create policy "Anyone can read writeups" on public.writeups
  for select to anon, authenticated using (true);
create policy "Owner can publish writeups" on public.writeups
  for insert to authenticated
  with check ((select auth.uid()) = 'OWNER_AUTH_USER_UUID'::uuid);

grant select on public.projects, public.writeups to anon, authenticated;
grant insert on public.projects, public.writeups to authenticated;
grant usage, select on all sequences in schema public to authenticated;
```

The project URL check is a useful database-side guard, while the owner interface also validates the GitHub host. If you change the schema or ownership model, update the SQL policies and the small set of selected/inserted columns in `js/app.js` together. The client uses Supabase query builder filters such as `.eq('id', id)`; it does not assemble SQL from URL or form input.

## Owner publishing

Open any page with `#pemos_admin`, or press **Ctrl + Shift + A**, then sign in with the owner account. The hidden entry point is only a convenience; it is not an authentication control. The browser signs in through Supabase Auth, and RLS checks the authenticated UUID on every insert. Markdown file uploads are read locally in the browser and are not uploaded as files; their text is saved in the `writeups.content` column. The article reader parses Markdown and sanitizes the generated HTML with DOMPurify before insertion into the page.

The frontend uses pinned CDN builds of Supabase JS, DOMPurify, Marked, and Highlight.js. For strict content security policies or offline deployments, self-host these dependencies and set an appropriate `script-src` policy.
